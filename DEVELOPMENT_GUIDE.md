## 📝 Как лучше предоставлять информацию

### Документы и спецификации:
1. **Markdown файлы** (`.md`) - лучше всего для документации, спецификаций
2. **Текстовые файлы** (`.txt`) - для заметок, логов
3. **Изображения** - PNG, JPG для дизайнов, скриншотов
4. **JSON** - для конфигураций, примеров данных

### Структура информации:
```
/attached_assets/
  ├── design_specs.md          # Спецификации дизайна
  ├── integration_guide.md     # Инструкции по интеграции
  ├── feature_requirements.md   # Требования к функциям
  └── screenshots/              # Скриншоты интерфейса
```

### Формат требований:
- **Четкие задачи** - конкретные, измеримые цели
- **Приоритеты** - критично/высокий/средний/низкий
- **Контекст** - описание проблемы и ожидаемого решения
- **Примеры** - примеры использования, если нужны

### Пример хорошего запроса:
```
Приоритет: ВЫСОКИЙ
Задача: Добавить валидацию email при регистрации
Описание: Пользователи могут вводить невалидные email адреса
Ожидаемый результат: Показывать ошибку при невалидном формате email
```
